# 0006 — WebView2 in the AOT launcher: generated COM bindings + static loader

**Status:** accepted (M2)

The official `Microsoft.Web.WebView2` .NET assemblies use built-in COM interop, which NativeAOT does not support.
The package's CsWinRT projection is AOT-capable but needs `Microsoft.Web.WebView2.Core.dll` (native WinRT) and
WinRT.Runtime next to the exe, which breaks "single exe ≤ 10 MB" (§9.1).

So the launcher:
- links `WebView2LoaderStatic.lib` from the SDK package (`DirectPInvoke` + `NativeLibrary`), no loader DLL on the disc;
- declares the ~20 interfaces it uses with `[GeneratedComInterface]`, generated by `scripts/gen-webview2.mjs`
  straight from the SDK's `WebView2.h` so vtable order cannot drift. Unused methods keep their slot with a
  placeholder signature; methods with unmappable types (VARIANT) are marked "do not call".

Result: `Baslat.exe` 8.7 MB, no trim/AOT warnings. Regenerate after an SDK bump:
`node scripts/gen-webview2.mjs %USERPROFILE%\.nuget\packages\microsoft.web.webview2\<ver>\build\native\include\WebView2.h`.
