# 0008 — "Maximum compatibility" encodes H.264 with OpenH264, not x264

**Status:** accepted (M3)

§10 requires an LGPL FFmpeg build (no `--enable-gpl`), so libx264/libx265 are unavailable. The BtbN LGPL build ships
`libopenh264` (BSD, Cisco), `libsvtav1` (BSD), `libkvazaar` (BSD, HEVC) and the hardware encoders.

"Maksimum uyumluluk" exists to play everywhere, so its target stays **H.264** (AV1 still needs a capable CPU/GPU on
older Windows 10 machines). Software encoding uses OpenH264 in bitrate mode — it has no CRF — with a resolution
ladder (≤480p 2.5, ≤720p 5, ≤1080p 9, above 20 Mb/s, maxrate ×1.5). Users with NVENC/QSV/AMF can pick them in
Ayarlar › Gelişmiş (constant-quality modes). HDR sources are tone-mapped (`zscale` + `tonemap=hable`).

Revisit if a GPL-compatible distribution model is ever chosen; nothing else would change.
